# MACE vs. AFL on TSPLIB

Reproduction package for the head-to-head comparison between **MACE** and
**AFL** ([An Agentic Framework with LLMs for Solving Complex Vehicle Routing
Problems](https://github.com/ZHANG-NI/AFL), ICLR 2026), reported in our response
to Reviewer 1, Comment 2.

TSP is the single problem both systems solve, so the comparison is run on
**TSPLIB**, the benchmark AFL's own paper uses for TSP. Both methods solve the
same 16 TSPLIB instances (51-1002 cities) under an identical **10-second
per-instance wall-clock budget**, and we report the tour length and its gap to
the known optimum (lower is better).

## Result

Averaged over the 16 instances, MACE's gap to the optimum is **1.36%** versus
AFL's **3.91%**; MACE produces a shorter tour on 15 of the 16 instances, with
`pr144` a tie (15 W / 1 T / 0 L). Per-instance numbers are in
[`results.json`](results.json).

## Contents

| Path | What it is |
|------|------------|
| `run_comparison.py` | Driver: runs both methods on all 16 instances, 10 s each, prints the table. |
| `tsplib/` | The 16 standard TSPLIB `EUC_2D` instances used. |
| `afl_solver/afl_tsp_solver.py` | The TSP solver **generated by AFL's own pipeline**, with a one-line VRP-to-TSP fix (relaxing a depot assertion) so it runs on TSP; the search logic is unchanged. |
| `afl_solver/afl_tsp_solver_original_gpt41.py` | The original, unmodified solver as emitted by AFL (GPT-4.1 backbone), kept for audit. |
| `results.json` | Per-instance tour lengths and gaps for both methods. |

AFL ships no TSP solver (its repository contains VRP variants only), so the
solver in `afl_solver/` had to be generated with AFL's own
`describe -> code_gen -> judge -> revise` pipeline. The MACE side uses the
repository's shipped 10-heuristic TSP portfolio and makes **no LLM call at solve
time**.

## Reproduce

```bash
# from a checkout of this repository (https://github.com/PJ-NTU/MACE)
cd comparisons/afl_tsp
python run_comparison.py --mace-repo /path/to/MACE
```

Requirements: `numpy`, `scipy` (the MACE portfolio's dependencies). **No API key
is needed** -- both solvers are already generated; solving is deterministic and
offline.
